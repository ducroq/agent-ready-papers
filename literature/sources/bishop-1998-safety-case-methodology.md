## Summary
The origin paper for the Claims-Arguments-Evidence (CAE) approach later developed at Adelard. It defines a safety case, lists its elements (claim, evidence, argument, inference rule), types of argument (deterministic, probabilistic, qualitative) and sources of evidence, and advocates "layered" safety cases built alongside the design ("design for assessment") as a living document. The text does not mention Toulmin.

## Key Findings
- Definition (PDF p. 2): "A documented body of evidence that provides a convincing and valid argument that a system is adequately safe for a given application in a given environment".
- To implement a safety case one must "make an explicit set of claims about the system", "provide a set of safety arguments that link the claims to the evidence" and "make clear the assumptions and judgements underlying the arguments" (PDF p. 2).
- Argument is defined as "linking the evidence to the claim, which can be deterministic, probabilistic or qualitative" (PDF p. 3).
- With independent arguments for the same claim, "the claim can be more robust, i.e. it can tolerate flaws in a single argument" (PDF p. 3).
- Living document (PDF p. 8): "the basic structure should remain broadly similar over time, but the status of the evidence will change".

## Relevance to agent-ready-papers
Probably the cleanest citation for the claims-arguments-evidence triad itself. Its requirement to state "assumptions and judgements" and its living-document view, where evidence status changes while the structure stays fixed, look close to how a claim registry tracks premise status across drafts. Paper 1 draft 2 could cite it alongside L103 as prior art and frame its contribution as carrying this discipline into academic prose, where the "regulator" is the reader or reviewer. The analogy is likely partial: safety cases face an external acceptance authority, which academic writing lacks.
